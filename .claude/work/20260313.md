## Thread ID normalization fix — `71ca030`

**Request:** Replies from external senders appear as separate inbox threads instead of being grouped with the original conversation.

**Root cause:** imapflow `envelope.messageId` returns message IDs with angle brackets (`<abc@hey.com>`), but mailparser `parsed.references` strips them (`abc@hey.com`). Root emails got `threadId = "<abc@hey.com>"` while replies got `threadId = "abc@hey.com"` — never matching.

**Plan:** Normalize all stored message IDs to bare format (no angle brackets) in the IMAP client. Re-add brackets only when constructing SMTP wire headers (RFC 2822 requires them there).

**Changes:**
- `src/lib/imap/client.ts` — added `normalizeMessageId()` helper; applied to `envelope.messageId` and `parsed.inReplyTo` in `RawEmailData` construction
- `src/app/(app)/inbox/[emailId]/_actions/reply.ts` — wraps `row.messageId` and `replyReferences` entries with `<...>` when passing to nodemailer SMTP headers

**Note:** Existing DB rows have angle brackets in `messageId`/`threadId`. A re-sync (or manual UPDATE to strip brackets) is needed for existing emails to thread correctly.
