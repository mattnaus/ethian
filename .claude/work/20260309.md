## NextAuth.js v5 auth flow

**Request:** Set up NextAuth.js v5 credentials-based authentication — login, register, session, and route protection.

**Plan:**
- Use NextAuth v5 `Credentials` provider with bcrypt password verification
- JWT session strategy (no DB sessions table needed)
- Protect `(app)/*` routes via middleware + server-side `auth()` check in layout
- Auth pages (`/login`, `/register`) in `(auth)` route group with shared centered layout
- Client-side forms using React 19 `useActionState` + Server Actions
- Root `/` page redirects based on session state

**Changes:**
- `src/auth.ts` — NextAuth v5 config: Credentials provider, JWT callbacks, session type
- `src/auth.d.ts` — Type augmentation to add `id` to `Session["user"]`
- `src/middleware.ts` — Route protection: unauthenticated → /login; logged-in auth pages → /imbox
- `src/app/api/auth/[...nextauth]/route.ts` — NextAuth route handler
- `src/app/(auth)/layout.tsx` — Centered card layout for auth pages
- `src/app/(auth)/_actions/auth.ts` — `loginAction` and `registerAction` Server Actions
- `src/app/(auth)/login/page.tsx` — Login page (server component)
- `src/app/(auth)/login/_components/login-form.tsx` — Login form (client, useActionState)
- `src/app/(auth)/register/page.tsx` — Register page (server component)
- `src/app/(auth)/register/_components/register-form.tsx` — Register form (client, useActionState)
- `src/app/(app)/layout.tsx` — Protected layout: redirects to /login if no session
- `src/app/(app)/imbox/page.tsx` — Placeholder Imbox page with sign-out
- `src/app/page.tsx` — Root redirect: /imbox if logged in, /login if not
