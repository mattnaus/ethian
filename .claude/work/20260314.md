## Fix pre-existing TypeScript build errors — `fa7b307`

**Request:** Fix "bunch of errors in the app interface" — build was failing; update workflow to run existing e2e tests before committing.

**Plan:**
Three root causes:
1. BullMQ v5 bundles its own ioredis, causing type mismatch when passing a top-level `IORedis` instance as `connection`. Fix: cast `redis as any` with an explanatory comment, and add the job name string literal as the third generic parameter on `Queue<>` so BullMQ v5's stricter `ExtractNameType` constraint is satisfied.
2. Worker `addBulk` passes `name: "process-email"` inferred as `string` rather than a literal — fix with `as const`.
3. `@types/nodemailer` was not installed, so `smtp/client.ts` had implicit `any` on the import.
Also updated `CLAUDE.md` Definition of Done to include `npm run build` and `npm run test:e2e` before committing.

**Changes:**
- `src/lib/queue/index.ts` — cast `redis as any` for queueConnection; added `"sync-account"` and `"process-email"` as third type params to `Queue<>`
- `src/lib/queue/workers/sync.worker.ts` — cast `redis as any` for workerConnection; added `as const` to `"process-email"` job name in `addBulk`
- `package.json` / `package-lock.json` — added `@types/nodemailer` as dev dependency
- `CLAUDE.md` — updated Definition of Done: build + e2e tests must pass before committing
