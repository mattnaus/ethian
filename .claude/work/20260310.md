## Fix 404s caused by createIntlMiddleware internal rewrites — `d9f3aea`

**Request:** App was returning 404 on all routes after the i18n changes.

**Plan:** Investigated `createIntlMiddleware` source and found it internally rewrites every request to `/en/[path]` via `NextResponse.rewrite()` even with `localePrefix: "never"`. Since the app has no `[locale]` route segments, Next.js 404s on all routes. Fix by removing `createIntlMiddleware` and manually setting the `X-NEXT-INTL-LOCALE` header — the header that `getLocale()`, `getMessages()`, and `getTranslations()` actually read from.

**Changes:**
- `src/middleware.ts` — removed `createIntlMiddleware` and `next-intl/middleware` import; replaced with `NextResponse.next({ request: { headers } })` that sets `X-NEXT-INTL-LOCALE: en` header
