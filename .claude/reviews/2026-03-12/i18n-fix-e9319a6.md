## Warnings

### Gatekeeper button shows the count twice
**File:** `src/app/(app)/inbox/_components/inbox-view.tsx:279-283` (desktop) and `:346-350` (mobile)
**Problem:** The button renders three spans in sequence: `t("gatekeeperLabel")` ("Gatekeeper:"), a pill badge with `{screenerCount}`, and `t("gatekeeperButton", { count: screenerCount })` ("5 new senders"). The ICU message `gatekeeperButton` is `"{count, plural, one {# new sender} other {# new senders}}"` — the `#` expands to the count, so the visible output is "Gatekeeper: **5** 5 new senders". Before this commit it read "Gatekeeper: **5** new senders" which was correct.
**Fix:** Either (a) create a new i18n key like `"gatekeeperSuffix": "{count, plural, one {new sender} other {new senders}}"` that omits the `#`, or (b) remove the separate pill badge `<span>` and let `gatekeeperButton` handle the full text including the number (restructuring the button markup).

## Suggestions

### The colon in `gatekeeperLabel` is a presentation concern
**File:** `messages/en.json:135`
**Note:** The value `"Gatekeeper:"` bakes punctuation into the translation string. In most i18n conventions, the colon would be part of the template or component markup, not the translated string, since other locales may not use a colon (e.g., CJK languages). For a single-locale app this is fine, but if a second locale is ever added it will need revisiting. Low priority given the project's current scope.
